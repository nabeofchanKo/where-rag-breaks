# 破棄した run — 実行環境が密閉されていなかった

**この run の数値を結論に使わないこと。**

## 何が起きたか

Arm A は「ツールなしで LLM を1回呼ぶ」と定義されている（SPEC §4-2）。ところが
Claude Agent SDK が起動する `claude` サブプロセスに、**実行者の環境に設定されていた
MCP サーバが読み込まれていた**。432 呼出中 217 呼出を実行した時点で、計測の
整合性チェックにより発覚した。

```
formula-09 k=8 forced: tool_calls=1 tool_names=['mcp__claude_ai_Claude_Docs__guide']
                       tool_results=1 denials=1 num_turns=2
```

## 影響の評価

- **外部データは漏れていない。** `denials=1` が示すとおり、ツールの呼出は権限で
  拒否されている。`tool_results` に数えられた 1 件は拒否メッセージ自体であり、
  モデルは抜粋以外の情報を得ていない。
- **ただし計測は汚れている。** 該当する 3 呼出は往復を1回余計に消費しており、
  トークン数とレイテンシがそのぶん増えている。さらに 1 呼出は
  `max_turns` 超過でエラーになり、回答が空になっている。
- **何より再現性がない。** 「ベースラインが実行者の手元の MCP 設定を見られる」
  状態で測った数字は、他人の環境で再現できない。公平な比較を前提にする
  ベンチマークとして、この run は成立していない。

## 対処

`arms/llm.py` に密閉設定を入れた（`mcp_servers={}` / `strict_mcp_config=True` /
`setting_sources=None` / `skills=None` / `plugins=[]`）。あわせて各呼出で
`tool_names` / `tool_results` / `permission_denials` を記録し、`eval/run.py` が
実行の最後に「ツールが結果を返した回数」を必ず表示するようにした。
Arm A でこれが 0 でなければ、その run は無効である。

そのうえで**全 432 呼出を最初からやり直した**。部分的に混ぜると、どの行がどの
設定で測られたのかが後から追えなくなるため。

## それでもこのデータを残す理由

破棄したこと自体が、このリポジトリがどう作られたかの記録になる。
途中経過の傾向（`formula` 難易度2 で棄権、難易度3 で囮を掴む）は
やり直した run でも再現している。
